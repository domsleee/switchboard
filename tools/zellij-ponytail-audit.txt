Runtime/cache limits and rejected false cuts
PluginCache is a per-session HashMap<PathBuf, Module>; loaders remove/reinsert cached modules and unload does not evict the module cache. Stores/instances/workers are separate allocations; the 16 MiB per-memory Wasmi limit is a ceiling, not a preallocation (nor a measured 64 MiB per plugin). Bounding inactive cache is a profiling lead, not a quantified fix: interpreter/Engine ownership must be checked before promising reclaimed code memory. [zellij-server/src/plugins/wasm_bridge.rs:178; zellij-server/src/plugins/plugin_loader.rs:184,338,511]
Dropping Distribution plugins by name does not remove embedded bytes; the code explicitly says so. Removing plugins_from_target does not shrink release builds: release already embeds assets/plugins. Removing test fixture assets or xtask/dev-only crates is not a stock executable saving.
Keep web_server_capability, terminal emulation, plugin ABI/permissions, and bars. Keep unwind behavior: changing panic to abort kills the session process and is not a behavior-preserving size cut.
Installed otool already links /usr/lib/libcurl.4.dylib, so “switch Mac curl to native” is not an installed-binary saving; omitting vendored_curl may avoid unnecessary vendored build dependencies for local builds, but Linux/static distribution tradeoffs differ. TLS/provider deletion is not supported: remote attach explicitly uses AWS-LC, while ring also has dev-only callers; lockfile presence alone does not prove duplicate production TLS engines.
Externalizing and compressing the same payload are alternatives, not additive savings. Lower RSS from either is unproven; compression adds load-time decode work.
